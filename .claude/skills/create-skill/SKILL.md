# スキルを作る

良いスキルは「うまくいっている実例」から作る。

## 手順

1. **材料を集める**: オーナーが貼った事例、うまくいった過去の成果物(`projects/`)、調べた一次情報。
2. **分析する**: うまくいっている理由を要素に分解する(構成・言い回し・タイミング・数字・ターゲット)。今のやり方との違いも書き出す。
3. **既存スキルを確認する**: `.claude/skills/` に似たスキルがあれば、新しく作らずそれを更新する。スキルが増えすぎると選べなくなる。
4. **SKILL.md を書く**: 置き場所は `.claude/skills/<名前>/SKILL.md`。名前は英小文字とハイフン。特定メンバー専用なら `<メンバーID>-<名前>` にする。

```markdown
---
name: <名前>
description: 何をするスキルか + どんなときに使うか(具体的な言葉で。これを見て使うかどうかが判断される)
---

# タイトル

## いつ使うか
## 手順
1.
## 良い例 / 悪い例
## チェックポイント
```

5. 長い参考資料・テンプレートは同じフォルダに別ファイル(例: `examples.md`)として置き、SKILL.md から参照する。
6. 専用スキルなら、そのメンバーの `.claude/agents/<id>.md` の `skills:` と `profile.md` に追加する。
7. 全社共通のスキルなら CLAUDE.md のスキル一覧に1行追加する。

## 注意

- description が曖昧だと使われない。「〜のとき使う」を必ず書く。
- 他人の文章をそのまま大量に転載せず、型・ポイントを抽出して書く。
