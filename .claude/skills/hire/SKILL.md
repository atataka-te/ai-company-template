# メンバーを採用する

人数を増やすこと自体に価値はない。採用は最後の手段。

## 1. 採用するか判断する

次のどれかに当てはまるときだけ採用する。当てはまらなければ、理由を添えて「今はまだ不要」とオーナーに返す。

- CEO が1人で抱える仕事量が多く、並列で進めないと間に合わない。
- 特定分野のスキルが増え、CEO がどれを使うべきか迷うようになった(その分野をメンバーに切り出し、使えるスキルを絞る)。
- 継続的に回し続ける専門業務がある(例: SNS 運用を毎日回す)。

## 2. 役職と責任範囲を決める

- `organization/org-chart.md` を読み、既存メンバーと責任が重ならないことを確認する。
- 役職名・名前・ID(英小文字。例: `cmo`)・責任範囲・成果指標を決める。
- 重要な採用なのでオーナーに提案して了承を取る(オーナーから指示された場合は不要)。

## 3. ファイルを作る

1. `organization/members/<id>/profile.md`
   ```markdown
   # <役職> プロフィール
   - **名前**:
   - **役職**:
   - **報告先**: CEO
   - **責任範囲**:
   - **成果指標**:
   - **性格・仕事のスタイル**:
   - **使うスキル**:
   ```
2. `.claude/agents/<id>.md`(サブエージェント定義。CEO が Agent ツールで呼び出す)
   ```markdown
   ---
   name: <id>
   description: <役職>の<名前>。<責任範囲>に関する仕事を任せるときに使う。
   skills:
     - <このメンバー専用のスキル名>
   ---

   あなたはこの会社の<役職>、<名前>です。報告先は CEO です。

   ## 最初に読むもの
   - CLAUDE.md と organization/rules/ のルール(必ず守る)
   - organization/members/<id>/profile.md
   - 指示された案件の projects/<案件名>/brief.md

   ## 責任範囲
   ...

   ## 仕事の進め方
   - 成果物は必ず projects/<案件名>/deliverables/ にファイルで残す。
   - 分からないことは推測せず、CEO への報告に質問として書く。
   - 最後に「結論・成果物の場所・残課題・CEO に判断してほしいこと」を報告する。
   ```
3. 専用スキルが必要なら `/create-skill` で `.claude/skills/<id>-<スキル名>/SKILL.md` を作り、agent の `skills:` に追加する。
4. `organization/org-chart.md` の組織図と表に追記する。
5. `management/decisions.md` に採用の決定を記録する。
6. CLAUDE.md の体制の記述が古くなっていれば更新する。

## 4. 仕事を振る

- メンバーへの指示は CEO が Agent ツールで `subagent_type: <id>` を指定して行う。独立した仕事は並列で振ってよい。
- メンバーの成果物は CEO が `/self-review` の観点で確認してからオーナーに報告する。
- 新しく作ったサブエージェントは、Claude Code を再起動するまで呼び出せないことがある。その場合は CEO が profile と agent 定義を読んで代わりに実行し、オーナーに再起動をお願いする。
